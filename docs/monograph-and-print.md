# The monograph, and what printing it would take

**Status: live.** Companion to [`traction-roadmap.md`](traction-roadmap.md),
which covers distribution. This covers the volume itself. Written 2026-08-05.

## What it is now

222 A4 pages generated by [`tools/build_monograph.py`](../tools/build_monograph.py)
from the catalogue, printed by headless Chrome. 328 Ruy López lines, every one
with an entry; 24 chapters; four indexes; a reproducibility block naming the
commit it was built from.

It is not primarily a book. It is an audit instrument that prints. Rendering
the catalogue is what surfaced the Wormald/Worrall conflation, seven games by
people who never played the match they were filed under, thirteen misspelled
world-championship participants, 221 player-name defects in the popularity
sidecar, a citation field leaking player names into the place column, and the
Modern/Robatsch contradiction. None of those were found by reading the data.

## Can it go into InDesign?

**A native `.indd` cannot be produced.** The format is closed and undocumented;
nothing outside Adobe writes one reliably.

**IDML can** — it is open, zipped XML, and InDesign opens it natively. It is
still the wrong trade. A faithful IDML of this volume means 222 pages of
threaded frames and 328 embedded vector diagrams, and the moment the catalogue
changes it is a hand-maintained document that no longer agrees with the data.
This week the catalogue changed on hundreds of rows. The generated volume
regenerates in seconds and was verified byte-identical after being moved
between directories; a laid-out one would have to be rebuilt by hand each time.

**And this was answered too quickly the first time.** The file-format argument
is sound and it skipped the obvious route: InDesign can be driven — it ships a
Scripts panel and ExtendScript, and every Adobe application on macOS answers
AppleScript. Having InDesign write the `.indd` is entirely possible. It is
still the wrong trade for the layout, for the reason above. It is a perfectly
good option for the one step left, the colour conversion, alongside Acrobat.

**What InDesign was actually wanted for here is prepress, and most of prepress
did not need it.** See below.

## What printing it would take

The current PDF is A4 exactly (209.9 × 297 mm), PDF-1.4, all fourteen faces
embedded and subset. What a printer would ask for and it does not have:

| | state |
|---|---|
| **bleed** | done. `--bleed` lays the trimmed page inside a 226 × 313 mm sheet and extends what must run off the cut |
| **crop marks** | done. drawn in the margin outside the bleed, so a mark never prints on the work |
| **TrimBox and BleedBox** | done. [`tools/set_pdf_boxes.py`](../tools/set_pdf_boxes.py) writes MediaBox 226 × 313, BleedBox 216 × 303, TrimBox 210 × 297 |
| **CMYK, or an output intent** | not done. Chrome emits RGB and Ghostscript is not installed here. Acrobat and InDesign both are, and both are scriptable |
| **PDF/X-1a or X-4** | not done, and follows the colour conversion |

```
python3 tools/build_monograph.py --bleed
# print to PDF with Chrome, then
python3 tools/set_pdf_boxes.py book.pdf --trim 210x297 --bleed 3 --marks 5
```

Without `--bleed` the output is exactly A4, as before, and that build is
unchanged: 222 pages, no overflow.

**The font gap is closed.** The faces here were the Google Fonts *latin*
subset, which stops at Latin-1, while the catalogue does not — `ć`, `č`, `ė`
and `ř` all appear in names, and Oldřich Duras was rendering one letter in
Times. [`tools/subset_fonts.py`](../tools/subset_fonts.py) now rebuilds
`web/fonts` from upstream with Latin Extended-A, which cost **under a kilobyte
per face**: 337 glyphs instead of 229, and the directory is still 140 KB.

The range is stated rather than derived from today's data, because subsetting
to exactly what the catalogue currently contains would rearm the same trap for
the next Czech or Lithuanian name.

An alternative typeface was never needed. Spectral itself covers all four; only
the file we shipped did not.

The result is a PDF with **ten embedded faces, none of them from the machine
that built it, and no span set in a foreign face** — verified with PyMuPDF, not
by looking. It was fourteen faces before, four of which were Georgia,
Helvetica and Times.

## Colour

One rule, adopted 2026-08-05: **gold marks a line that carries documentary
evidence, and nothing else.** Before that it was carrying family identity,
board squares, bar length, treemap share, the draw segment of a result split,
"still played", and three kinds of rule — eight meanings, which is none.
Quantities are ink at varying weight. The cover keeps the band and the letter,
because that is identity rather than data.

Anything added to this volume follows that rule or argues with it in writing.

## Next, in order

1. **Colour conversion.** The geometry, marks and boxes are done; what remains
   is RGB to CMYK with a stated profile and a PDF/X output intent. Either
   `brew install ghostscript`, or script Acrobat or InDesign, both installed.
2. **Deploy the explorer.** `web/dist` was last built 2026-07-31 and the
   catalogue changed on 08-03; production still shows the retracted Worrall
   attribution and the misspelled participants.
3. **The README asks nobody for anything.** One sentence — "corrections and
   additions welcome via issues" — buried in a paragraph about release notes.
   No offer of the data to Lichess, ChessBase or chessgames.com, which is the
   whole distribution argument of the traction roadmap.
4. **Working names.** 2,144 of 5,899 rows carry no alternative name. The
   `known-as` relation exists for it now. This is the project, not a task.

## What is deliberately not being done

**Two populations.** Three separate review panels have recommended splitting
the volume into rich entries plus a compact register, and the argument is
sound: 222 pages of equal typographic weight over 10 sourced attributions is
effort spent on practice when the subject is names. Albert has chosen the
complete corpus repeatedly and that choice stands. It is recorded here so the
next reviewer who raises it can see it was heard.

**The six evidence figures** Codex proposed — an evidence-status matrix, a
crosswalk against other catalogues, an alias genealogy, an attestation
histogram, a ranked list of contemporary names absent from OCN, and source
coverage by language. They are the right figures and they describe a different
book. Building them before the working-names layer exists would be drawing a
2,144-row hole in great detail.
